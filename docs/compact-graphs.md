# Компактная проверка граф

Контракт `resources/registry/graph-editors.im40.v3.json` задаёт редактор каждой из 54 основных граф. Старые `fieldBindings` служат источниками фактов, но не создают дополнительные поля интерфейса. Вложенные позиции 15а, 17а и «В» сохраняются в родительских графах.

| Графы | Видимый ввод |
|---|---|
| 2, 8, 9, 14, 18, 21, 29, 30, 31 | Один полный текст, без шаблона адреса |
| 19, 20, 24, 36, 37 | Одно составное кодовое значение; формат описан рядом с редактором |
| 6 | Количество мест и необходимые связи общих групп с товарами |
| 11, 15, 16, 25, 26, 33, 34 | Код из соответствующего справочника |
| 22, 23 | Валюта; курс, кратность и основание ручного резерва |
| 35, 38, 42 | Масса брутто, нетто и стоимость всей товарной позиции |
| 39, 41 | Количества и единицы по применимости |
| 44 | Один список документов с официальными кодами и реквизитами |
| 54 | Дата составления и один текст составителя/полномочий |
| 1, 5, 12, 17, 32, 43, 45–47 | Профильные значения и результаты только для чтения |

14 неприменимых граф видны в общей сетке и не блокируют переход. Проверка ресурса: `node --test tests/graph-editors.test.mjs`.

Проекция `graphProjection.editors` добавляет компактные значения к существующим извлечённым фактам. Текст хранится в `draft.graphTexts` по адресу графы и товара; исходные части адресов остаются в модели, но не определяют полноту принятого текста. Проекция сама не меняет revision, идентификаторы, файлы, OCR и TTL. Старая сборка сохраняет добавочные данные при чтении; откат требует согласованного frontend/backend комплекта, без очистки временной сессии.

Предложения составной графы собираются по документу. Совместимые частичные сведения объединяются с раздельными цитатами; при противоречии остаются целые предложения каждого источника. Декартово произведение имён и адресов не создаётся. Одинаковые тексты объединяют источники. Ручной текст сохраняется при remap, новый конфликт доступен для подтверждения; удалённая цитата не показывается источником ручного текста.

Первое открытие старой сессии переносит прежние нормативные значения в `legacyStatutory` в пределах того же TTL. Новые значения и источники отражены в `migrationNotices`, расчёт становится неактуальным. Идентификаторы, OCR и факты поставки сохраняются; миграция записывается под блокировкой сессии и не повторяется при refresh. При откате сохраняйте весь JSON с добавочными полями и используйте согласованный предыдущий комплект; нормативные значения прежней версии доступны в legacy-области, а расчёт после переключения версии нужно выполнить заново.

`PATCH /api/draft` принимает атомарный массив `changes` с текущей `revision`. Текстовая правка: `{graphId:"2",entityId:null,value:"Полный текст"}`; выбор источника дополнительно передаёт `candidateId` текущего предложения этой графы. Обычные числовые/кодовые правки сохраняют `fieldId`. Неверный новый числовой ввод хранится в `invalidInputs`, показывается в том же контроле и блокирует использование прежнего числа. Ошибка версии/сети не требует повторного OCR; клиент сохраняет локальный несохранённый ввод.

Составные форматы: 19 — `Нет` либо `Да; контейнеры`; 20 — `CPT; ALMATY`; 24 — `010; 00`; 36 — `Нет; ОО; ОО; ОО; ОО` (признак льготы и четыре кода, при льготе далее основание); 37 — `40; 00; 000`. Графа 44: `04021 | INV-1 | 2026-10-28 | 0 | Инвойс` по одной строке на документ. После названия возможны ещё две колонки дат действия. Название можно опустить — используется официальное. Перестановка строк сохраняет ID; несколько сканов одного документа не создают несколько юридических записей. Неоднозначное одновременное изменение нескольких документов одного вида требует сохранения одной строки отдельно. Произвольные внутренние ID не читаются из текста. Неразбираемый текущий текст остаётся видимым с примером, а расчёт по прежним скрытым значениям запрещён.

Проверка перехода использует manifest: непустой описательный текст, необходимые кодовые части, числа и единицы, курс валюты инвойса и реквизиты обязательных документов. Пустая графа 8 блокирует переход даже при полной арифметике. Город/улица/индекс отдельно не требуются для принятого полного текста участника. Ошибки списка документов ведут в 44, связей упаковки — в 6, состава товара — в 31; каждый товар проверяется отдельно. Кнопка перехода подтверждает актуальный состав товаров без скрытого checkbox. Будущие суммы, отсутствие файла само по себе и неприменимые графы не являются ошибками заполнения.

Расчёт повторяет проверку граф и дополнительно проверяет ответы ДТС метода 1, участников продавца/покупателя, фактические расходы и распределения, все необходимые курсы и применимость серверного профиля. Старые отдельные адресные поля отправителя/получателя повторно не требуются. Отсутствующий нормативный профиль объясняется датой/контекстом, а не предложением вручную ввести НДС. Прямой запрос calculate не обходит review gate.

Внешняя геометрия: `GraphCard` — рамка с номером на верхней границе, названием слева и редактором справа. Общий токен `--graph-card-height` равен 176 CSS px на широком экране и 220 px на узком; все 54 карточки имеют одинаковые размеры в данной компоновке. Длинные значения, дополнительные строки и ошибки прокручиваются внутри. Источники открываются поверх потока в portal с ограничением по видимой области; доступны hover, фокус и нажатие. При увеличении масштаба применяется общая адаптивная компоновка.

Описательные графы имеют ровно один textarea. Графы 22/23/35/38/41/42/54 содержат объявленные валютные, числовые и датовые контролы; единицы 41 подставляются по коду, при двух единицах нужны оба количества. Позиции 15а/17а/«В» отображаются внутри родителей без новых основных карточек. Графа 44 редактируется единым списком, подробные карточки юридических документов не возвращаются. Несохранённые тексты и числовой ввод переживают переключение товара/страницы в памяти текущей сессии; новая сессия очищает этот буфер, история в браузере не сохраняется.

Источник документа содержит страницу либо лист/ячейку и точную цитату. Источник нормативного значения содержит официальный URL, период и версию правила. Ручной текст не выдаётся за цитату. Если после remap появился один новый документ, противоречащий ручному значению, доступны два разных результата: новый документ и сохранённое ручное значение. Это позволяет сохранить свой ввод или выбрать источник без скрытой блокировки. Одинаковые результаты дополнительных кнопок не создают.

Изменение даты 54 или валюты 22 запрашивает соответствующие курсы; котировка другого дня не принимается. Значение и номинал раздельны, в том числе номинал 100. Смена кода/происхождения/льготы/версии правил пересматривает применимость и связанные единицы. Несовместимые количества очищаются; введённый вручную код сохраняется. Общие суммы следуют составу позиций, общий паллет не удваивается при нескольких товарах.

Возврат с расчёта сохраняет графы и источники. Любая правка операнда делает 12/45–47 ожидающими нового расчёта; старый результат не принимается как актуальный. Результат содержит ревизию и hash нормативных правил. Ошибка авторизации или поздний ответ не запускают новую сессию, не стирают соседнее поле и не повторяют OCR. Ошибка расчёта, относящаяся к исходной графе, возвращает к её видимому редактору. В графе 44 противоречия разных документов разрешаются по одному без подмены других записей; подтверждённые номера защищены от remap.
