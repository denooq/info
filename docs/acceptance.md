# Локальная приёмка MVP · 12.11.2026

Это исторический отчёт предыдущего четырёхстраничного профиля. Текущая трёхстраничная версия проверяется по [acceptance-graphs.md](acceptance-graphs.md); экспорт в ней отключён.

Реализованы четыре страницы согласованного интерфейса, изолированная временная сессия, OCR/Mistral Small, форма из реестра, обязательность и конфликты, товары/документы/места, расчёты, подтверждение и выдача PDF/ZIP. Нет БД, регистрации, истории, отправки в Keden или ЭП.

Проверки выполнялись на Windows с PHP 8.3.36 / memory_limit=192M и Node 26.13.0. Node и браузер используются только при разработке; production работает на PHP и готовой статике.

Фикстуры генерации используют документальные значения и **явно синтетические ручные подтверждения** для отсутствующих в первичке реквизитов. Это тест программной обработки, а не готовые реальные декларации. Полностью автоматическое заполнение не подтверждено: [пропуски и расход реального AI](document-ai-evaluation.md). Пользователь должен проверять кандидаты, роли, товары, правовые коды, ставки и обязательные ответы.

Оставшиеся предварительные правила: полнота классификаторов/ДТС, применимость сбора в базе НДС, подтверждение участка перевозки FCA, различение уплаты и начисления. Техническая ссылка UUID и расширения Keden проверены только локальным профилем. Непредставленные ветки блокируются: [границы XML](xml-profiles.md).

Доработка ТН ВЭД v2 от 13.11.2026: 69 PHP-проверок, 12 Node-проверок и 4 браузерных сценария проходят без платных API-запросов. Проверены все 13294 формулы, пять видов ставок, нулевая ставка, две дополнительные единицы, точные преобразования количества, валютный номинал, итоговое округление, ручные правки и подтверждение применимости. Браузер проверяет подстановку, запрет расчёта до подтверждения и пересчёт изменённой специфической ставки. Импорт использует около 156 МиБ при локальном лимите 192M. Это проверка программных формул и данных; действующая ставка и исключения Казахстана в JSON не разрешены автоматически.

Исправление грузовых мест: полный PHP-набор проходит 72 проверки. Браузерный сценарий проверяет путь от пустых обязательных списков через создание общей группы у поля до расчёта для двух товаров: 34 места учитываются один раз. Проверены ошибочный ввод без создания строки и сохранение ввода после отказа запроса. Проверка компактной формы на desktop/mobile также проходит. Backend и готовый frontend нужно обновлять вместе.

Исправление добавления строк и активной сессии: 73 PHP-проверки и 19 Node/браузерных проверок проходят. Итоговый Node-набор запускается с `--test-concurrency=1`, чтобы несколько Edge-процессов не искажали локальные таймеры. Проверены клик «Добавить» прямо после ввода во всех трёх разделах, сохранность незавершённого ввода соседнего поля и формы при 401/410 без нового POST сессии или повторного OCR. Отдельный реальный HTTP-тест проверяет cookie, продление срока активности, сохранность файлов документов/OCR за первоначальным сроком и запрет возрождения истёкшей сессии. На фактическом хостинге эти изменения ещё не проверены.

Причины блокировки расчёта и cron: 74 PHP-проверки и 21 Node/браузерная проверка проходят. Присланные четыре ошибки воспроизведены синтетическими данными: нет инвойса 04021 и контракта 03011, нет USD, не подтверждён расход ДТС. Проверены полный список, переходы к разделам/ответу ДТС и доступность расчёта после исправления без загрузки/OCR. Тихий cron действительно удаляет просроченную тестовую сессию, сохраняет активную, не выводит успешный результат и оставляет stderr/ненулевой статус при ошибке. Переключение задачи с PHP 5.2 на 8.3 требует действия владельца Plesk; оно не выполняется обновлением Git.

Дата составления и НБК: 80 PHP-проверок и 22 Node/браузерные проверки проходят без платных AI-запросов; production-сборка проходит. Новый черновик получает текущую дату Казахстана, расчёт связан с ней. Реальный XML из 48 валют сохраняет кратность 100 для KRW; смена даты, кэш, отсутствие валюты, небезопасный XML, ошибки НБК и конфликт ревизий проверены. Браузер подтверждает автоматическую загрузку USD/валюты инвойса, сохранение ручной правки, явную замену официальным курсом и переход к расчёту без повторного OCR. Прямой HTTPS-запрос PHP с полной TLS-проверкой также успешен. Подробности: [курсы НБК](exchange-rates.md).

Обязательные документы без «Добавить»: 83 PHP-проверки и 23 Node/браузерные проверки проходят, production-сборка проходит. При отсутствии записей сразу видимы поля инвойса 04021 и контракта 03011; открытие страницы не записывает фиктивные документы. Проверены создание по первой правке, повторное использование найденной записи и её источников, сохранность соседнего ввода/фокуса и ввода после ошибки, обновление страницы и расчёт без повторной загрузки/OCR. Реальный HTTP проверяет ту же операцию с ревизиями и сохранностью первичных файлов. Обязательность реквизитов сохранена.

Проверка на фактическом PS.kz XS остаётся невыполненной: нет доступа к развёрнутому экземпляру. Пользователь сообщил, что самостоятельно сменил версию PHP для cron; это учтено, удалённая проверка не заявляется. Требуются результаты PHP/cron/HTTPS к Mistral и НБК, двух сессий, времени и ресурсов обработки, генерации и очистки на реальном аккаунте. Локальные результаты не заменяют её. Инструкция: [PS.kz](ps-kz-xs.md).
