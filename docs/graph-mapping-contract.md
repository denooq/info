# Сопоставление полного комплекта с графами

`Mapper` отправляет один логический набор: версионированный реестр граф и полей ДТС, сведения о владельце/применимости/приоритете каждого поля и все доступные OCR-блоки, строки таблиц, ячейки и листы XLSX из манифеста сессии. Если весь набор не помещается в ограничение контекста, Pipeline создаёт окна источников; каждое окно всё равно содержит полный реестр граф. Pipeline не запускает отдельные запросы на один документ и техническую группу полей.

Каждый фрагмент источника содержит стабильный `sourceId`, имя и код вида вложения, страницу или координату листа, язык и распознанный текст. Ответ использует строго `graph-mapping-v2`: товарные позиции, результаты по графам (`found`, `conflict`, `not_found`, `incomplete`), отдельные записи supporting documents, факты ДТС, запросы справочников и запросы недостающего контекста. Сервер связывает AI-ключи с ID сессии; для DTS-1-2 факт стороны содержит явную `participantRole`.

`knownGoods` и `knownDocumentRecords` передаются последующим окнам. Модель повторно использует их backend key для той же сущности. Для точных копий вложенного юридического документа backend дополнительно сверяет хеш файла, расположение и цитируемые реквизиты; разные документы внутри одного PDF остаются отдельными записями. Роли seller/buyer/consignor/consignee/declarant/financial сохраняются как независимые устойчивые ID вида `party-<role>`.

Кандидат содержит дословное `rawValue`, каноническое значение, единицу/валюту и одну или несколько цитат. Приоритет графы определяет порядок оценки источников, но не скрывает разногласия и не запрещает использовать доступный fallback. Вид документа и роль участника дают приоритет, но сами по себе не запрещают семантически подтверждённый кандидат. Ответ ссылается на реально просмотренные sourceId. Отсутствие в неполном окне остаётся `incomplete`; `not_found` допустим только после полного прохода всего комплекта. Backend проверяет структуру и типы результата, принадлежность ссылок текущему manifest, наличие `rawValue` в цитатах и каноническое преобразование для дат, кодов и чисел.

Смысловую проверку выполняет AI по всем переданным текстам: буквальное слово `gross`/`net` не является обязательным, если контекст документа однозначно указывает смысл массы. При этом масса должна иметь подтверждённую единицу, а денежная сумма — подтверждённую валюту. Число, непосредственно записанное с единицей массы или валютой, не принимается как номер юридического документа. Неизвестная приоритетная позиция остаётся доступным fallback, а не ошибкой источника.

AI не владеет значениями с владельцами `profile`, `calculated` и `not_applicable`. Для владельца `reference` он может сформировать поисковый запрос, но не присваивает код без backend-справочника. Неподтверждённое значение отсутствует; оно не заменяется пустой строкой или текстом-заглушкой.

Источники и результаты остаются в изолированной временной сессии. Usage и версия prompt сохраняются рядом с результатом для диагностики запроса; секрет API в контекст не передаётся.
