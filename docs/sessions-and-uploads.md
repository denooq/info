# Временные сессии и документы

Анонимная сессия создаётся POST /api/session, её непрозрачный секрет хранится в HttpOnly/SameSite cookie. Каталог сессии определяется хэшем секрета, сам секрет не хранится в JSON и не передаётся в URL. GET /api/session возвращает только разрешённое представление текущей сессии и CSRF-токен для изменяющих запросов.

Загрузка: POST /api/documents, multipart-поля file и revision, заголовок X-CSRF-Token. Имя файла отображается как метаданные, на диске используется случайный серверный идентификатор. Проверяются фактический MIME, структура/читаемость, расширение, размер, страницы/листы, распакованный XLSX и общий диск. Приём каждого файла отдельный: ошибочный не уничтожает ранее принятые. DELETE /api/documents/{id} с JSON revision удаляет только документ текущей сессии.

В профиле `im40-kz-graphs` multipart также требует `groupId`. Выбор официального результата мышью/Enter сразу вызывает POST `/api/upload-groups` с `{revision,code,version,action:"add"}` без отдельного «+ Добавить». Группы возвращаются в `uploadGroups`; файл сохраняет groupId/documentKind/classifierVersion. Повторное добавление вида сохраняет вложения. `action:"type",id,code,version` меняет вид группы, объединяя с существующей; `action:"remove",id` удаляет строку вместе со всеми её вложениями одной mutation/revision. PATCH `/api/documents/{fileId}/type` с `{revision,groupId}` переносит отдельный файл, включая старый файл без вида. Изменение вида не меняет id/hash/status/OCR; оно инвалидирует сопоставление через fingerprint. Квоты считаются суммарно по сессии, не по группе. Пустая группа не создаёт юридический документ или данные графы 44.

Удаление одного файла и строки использует общую очистку: ссылки на удалённые файлы и цитаты убираются из кандидатов, записей документов и исходных строк; оставшиеся источники и OCR сохраняются. Автозначение без источника пересматривается, выбранные/ручные сведения остаются пользовательскими данными без ложной цитаты. Mapping и расчёт инвалидируются. Физические удаления записываются в приватный pendingFileCleanup и ограничены проверенными путями documents/ocr своей сессии. При отказе файловой системы существующий cleanup повторяет их, затем действует TTL. Публичный JSON не содержит этих путей. Активные OCR/mapping блокируют загрузку, удаление и исправление вида также на сервере.

Схема сессии 2 добавляет группы и профиль. Старые сессии без schemaVersion читаются как версия 1: файлы, OCR, id, ручные данные, цитаты и TTL сохраняются; файлам назначается null-вид до выбора. Старый ready/generating/calculated возвращается к проверке, подтверждение и опубликованные артефакты снимаются, задания генерации отменяются; физические файлы остаются под общей очисткой TTL. Миграция добавочна для draft и не запускает OCR. Неизвестная версия получает SESSION_VERSION, без молчаливого сброса. Для отката сохраняйте предыдущий release и закрытую копию runtime до первого изменения: восстановление старой сборки само по себе не возвращает снятые подтверждения. Не размещайте копию runtime в Git/web-root.

PDF с современными сжатыми объектами проверяются smalot/pdfparser, с ограничением декодирования и без хранения изображений. Бесплатный FPDI из mPDF оказался недостаточен для предоставленных входов; это не использовано как повод отклонять исправные документы. Защищённые паролем и незавершённые PDF отклоняются. Таблицы читаются как ячейки, макросы не выполняются, рисунки не распаковываются в объектную модель. Для изображений проверяется возможность декодирования с оценкой безопасной памяти.

Состояние записывается атомарно и защищается блокировкой. Изменяющий запрос содержит ожидаемую dataRevision: устаревшая версия получает REVISION_CONFLICT. Правки инвалидируют расчёт и результаты, сохраняя документы и OCR. `session_ttl` — срок бездействия (по умолчанию два часа); успешные авторизованные правки, добавление/удаление строк и другие пользовательские операции продлевают его и cookie вместе. Чтение состояния и worker срок не продлевают. `php bin/cleanup.php` удаляет просроченные документы, OCR, состояние, задания и результаты даже при закрытом браузере. Настроить PHP-задачу Plesk раз в минуту, если такой интервал доступен; отказ в доступе действует точно по TTL, физическое удаление — ближайшим успешным циклом. Истёкшая сессия не возрождается поздним запросом.

SESSION_REQUIRED означает отсутствие/неверный формат cookie, SESSION_EXPIRED — недоступность или истечение серверной сессии. Интерфейс оставляет текущую форму и несохранённый ввод, предлагает «Проверить сессию» через GET и не создаёт новую автоматически. Уже удалённые серверные данные восстановить нельзя; новая загрузка начинается только явным действием. Проверять cookie на том же домене/протоколе, HTTPS и разрешение cookies в браузере; токен и ключ не передавать в URL или журналах.

Очередь сохраняет задания в JSON сессии: queued/running/done/failed/cancelled, lease и ограниченные попытки. Опрос API читает состояние, не выполняет задания. Worker не держит блокировку сессии во время внешнего запроса; тяжёлые этапы и preflight-загрузка ограничены общей блокировкой. Истёкшее задание может возобновляться с контрольной точки либо завершаться ошибкой; поздняя генерация не публикуется для другой ревизии.

Чужая сессия, неправильный CSRF или Origin отклоняются. Публичное представление не содержит секрет доступа, пути хранения или leaseOwner. Закрытые URL config/src/vendor/reference и служебные каталоги не отдаются через web-root. Ошибки HTTP возвращаются структурированно, без исходного текста провайдера, ключей, стеков и временных путей; содержимое документов не пишется в журналы. Отдельного административного интерфейса нет.

Проверка HTTP: при запущенном PHP-сервере `node tests/http-smoke.mjs`. Она проверяет две cookie-сессии, CSRF, загрузку, запрет чужого удаления и закрытые пути. Тест создаёт только временную сессию, удаляемую по общему TTL.

Для локальной и серверной загрузки лимиты PHP upload_max_filesize/post_max_size должны позволять выбранный лимит приложения. На стандартном PHP это может быть 2M/8M; check-platform показывает фактические значения. Нельзя считать настройку приложения 10 MiB доказательством настройки PHP/Plesk. Если тяжёлая обработка занята, загрузка возвращает PROCESSING_BUSY без потери ранее принятых документов.
