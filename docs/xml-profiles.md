# Профили XML MVP

По решению пользователя от 12.11.2026 MVP выгружает XML по двум предоставленным образцам. Официальная XSD-проверка переносится на следующий этап и не блокирует типовые поддержанные случаи. Статус комплекта: «Профиль примера проверен; XSD не выполнялась; импорт Keden не проверен».

`resources/xml-profiles/dt.v1.json` и `dts.v1.json` содержат только структуру образцов, пространства имён, порядок дочерних элементов, атрибуты классификаторов, путь источника и SHA-256. Значения чужой декларации в шаблоны не переносятся. ДТ сохраняет CA 1.10.3 / common 0.4.16, ДТС — CA 1.8.1 / common 0.4.14. Общие структуры участника и подписанта повторно используются по наблюдаемым типам; это локальное правило MVP, не доказательство соответствия официальной схеме.

ДТ содержит поля поставки, участники, транспорт, товары, документы и начисления. Сбор выгружается как рассчитанная сумма; фиктивная ставка «6 МРП» из чужой декларации не присваивается. Если фактическая уплата не указана, записи уплаты не создаются. ДТС содержит явные ответы метода 1, основания, цену по курсу и итог начислений в наблюдаемом `Method1AddCostsDetails/TotalAmount`. Разбивка расходов хранится в подтверждённых данных и расчёте; новые имена XML для отсутствующей детализации не создаются.

Временные ограничения экспорта: ненулевые вычеты и косвенные платежи, контейнерные номера, отгрузочные спецификации/справочный номер/отсрочка, квоты, предшествующие документы, дополнительные единицы и преференциальные основания с ненаблюдаемыми ветками. Для взаимосвязи, ограничений использования и условий стоимости, требующих дополнительных сведений, экспорт также блокируется. Данные можно вводить и рассчитывать; сообщение указывает адрес поля и необходимость расширения профиля. Это согласованная граница до получения XSD, а не молчаливое игнорирование заполненных полей.

Ссылки ДТ–ДТС используют UUID текущего комплекта. Они не имитируют S-идентификатор записи Keden или таможенный регистрационный номер. GoodsItemOrder, Ntincode и данные FillerInformation берутся из текущей подтверждённой формы. НТИН не назначается автоматически.

Локальная проверка отклоняет внешние сущности, неверные namespaces, неизвестные элементы, нарушения наблюдаемого порядка, неверные десятичные/целые значения и несовпадение товаров, стоимости, кодов представления и платежей с snapshot. Это не заменяет официальные XSD. `SchemaValidator` сохранён как подготовка будущего офлайн-контроля; текущий путь экспорта его не вызывает.
