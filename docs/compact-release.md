# Комплект компактной формы и обновление данных

Собирать frontend, backend и resources одной версии. Старый frontend не понимает `graphProjection.editors`; обновление только CSS или только PHP не даёт согласованной формы.

```powershell
npm run build
php bin/build-release.php
php tests/release-smoke.php
```

Архив `release/customs-declaration-mvp.zip` содержит production-зависимости и `release-manifest.json`. Manifest фиксирует версии комплекта, исходного реестра, редакторов, нормативного ресурса и SHA-256 каждого включённого файла. `registryVersion=2.0.0` и `schemaVersion=2` сохраняются для исходных фактов и добавочной миграции; `editorVersion=3.0.0` обозначает новый контракт формы. Нормативный ресурс имеет отдельные версию, период и источники.

Проверка распаковывает архив в отдельный временный каталог, проверяет все hash и отсутствие частных/исследовательских файлов. Затем загружает API реестров, создаёт сессию, сохраняет текст графы, проверяет миграцию, добавление/удаление вложения и запрет экспорта. Ресурсы frontend проверяются по ссылкам в собранном index.html. Тесту не нужны ключ, reference или сеть.

## Сохранение частных данных

`config/local.php`, переменные окружения и существующий каталог runtime не входят в архив и не заменяются сборкой. Не распаковывать комплект с удалением содержимого runtime. Публичным корнем остаётся только `public/`. Никаких действий на PS.kz это изменение не выполняет и не требует для завершения локальной приёмки.

## Миграция текущей сессии

Миграция добавочная: прежние факты, идентификаторы, файлы, OCR/checkpoints и TTL сохраняются. Первое открытие переносит прежние нормативные значения в `draft.legacyStatutory`, добавляет `compactVersion`, `ruleResourceHash`, `statutoryRules` и уведомление со старыми/новыми величинами. Предыдущий расчёт снимается; требуется пересчёт, повторная загрузка документов не нужна. Запись выполняется под существующей блокировкой, повторный refresh не мигрирует ту же версию ещё раз.

Полные тексты граф хранятся в `draft.graphTexts`; недопустимый текущий числовой ввод — в `draft.invalidInputs`. Нельзя удалять эти добавочные поля при копировании JSON. Они живут только до удаления временной сессии. Обновление нормативного ресурса также снимает расчёт, даже если факты поставки не менялись.

## Откат

Сохранить предыдущий согласованный комплект frontend/backend/resources и резервную копию приватной конфигурации и активного runtime до замены файлов. Откатывать программный комплект целиком; не очищать текущие сессии и не подменять runtime устаревшей копией с потерей новых правок. Добавочные ключи должны сохраняться старым читателем JSON; старый интерфейс не отображает принятые полные тексты новой формы, поэтому возвращать его пользователю для продолжения заполнения без проверки данных нельзя.

Прежние нормативные значения доступны в `legacyStatutory` только в пределах исходного TTL; автоматического восстановления старых ставок нет. При возврате новой версии выполнять её миграцию и новый расчёт. Если требуется полное восстановление runtime из копии, сначала согласовать новые изменения с копией; такой перенос данных не входит в автоматическую миграцию. Резервные копии должны соблюдать прежние ограничения временного хранения.
