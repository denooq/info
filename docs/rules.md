# Предварительные правила MVP

Профиль `resources/registry/rules.v1.json` дополняет поля общими и межполевыми ограничениями ИМ 40 KZ / ДТС-1 метода 1. Он не является заключением о юридической полноте. Обязательность каждого поля хранится в fields.v1.json, а правила коллекций, применимости и согласованности — здесь.

До расчёта требуются все применимые исходные сведения, а не только суммы и курс. Для каждого товара отдельно нужны код, происхождение, массы, стоимость, документы, ставки и основания. Для каждой из шести ролей участников нужны собственные реквизиты либо явная связь sameAsRole без цикла. Для KZ требуется БИН/ИИН; иностранный идентификатор не выдумывается.

Метод 1 требует явных ответов о взаимосвязи, ограничениях, условиях цены, лицензиях/роялти и выручке. Взаимосвязь сама по себе не запрещает метод: проверяются влияние на цену и подтверждающие сведения. Положительный ответ об ограничениях требует подтверждения их допустимости; неоценимые условия сделки не обходят блокировку. Отсутствие ответа отличается от false.

Все категории добавлений/вычетов имеют явный ответ о применимости. При true нужны строки с суммой, валютой, включённостью в цену, основанием и распределением; при false нельзя молча учитывать скрытые расходы. Подтверждённый ноль допустим, неизвестная сумма не превращается в 0. Неприменимость поля допускается только если условие requiredWhen ложно; пометка пользователя не отменяет условно обязательное поле.

Табличные проверочные случаи входят в acceptanceCases профиля. Дополнительно обязательны межполевые проверки: нетто ≤ брутто; отсутствие двойного учёта строк и упаковки; существующие ссылки на товары/документы; курсы соответствующей даты/кратности; согласованное распределение; разделение начисления и фактической уплаты.

Спорные положения перечислены в provisionalQuestions с последствиями для MVP: полнота правил ДТС/справочников, дата и основание платежного профиля, округление графы B, участок FCA-перевозки и оболочка Keden. Они сообщаются пользователю, но не служат дополнительным предварительным согласованием каждого поля. Точные XSD-проверки и результаты размещения нельзя считать выполненными заранее.
