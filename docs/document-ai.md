# Document AI и обработка

PDF/изображения распознаются серверным HTTP-вызовом Mistral OCR 4.1 (`mistral-ocr-4-1`); ключ берётся из закрытой конфигурации. В браузер передаются только принадлежащие сессии результаты/ошибки. Новый ключ следует задавать в config/local.php либо MISTRAL_API_KEY; проверка конфигурации сообщает только факт настройки, без значения.

Обработка выполняется `php bin/worker.php`, ограниченным числом заданий за запуск. В Plesk использовать тип «Выполнить PHP-скрипт», с выбранным PHP 8.3 и доступным расписанием. Постоянный worker и shell_exec не используются. Отдельно запускать `php bin/cleanup.php` для очистки. Нельзя считать поддержку расширений и cron на локальной машине доказательством настройки PS.kz.

OCR запрашивает blocks, HTML-таблицы и уверенность по блокам, без изображений Base64 в ответе. PDF передаётся закрытым Base64-вызовом; публичные ссылки не создаются. За один этап берётся до восьми страниц обычного OCR: это технический размер задания, не ограничение всего документа. Исходные индексы сохраняются, UI-страницы начинаются с 1. Пропущенная/дублирующаяся/неверно пронумерованная страница — ошибка, не разрешение молча усечь контракт. Повёрнутые страницы передаются в исходном документе; реальное качество их распознавания ещё требует прогона.

Успешная часть сохраняется отдельно с hash исходного файла, моделью и индексами страниц. Повтор использует сохранённую часть; распознавание другой части не оплачивает уже сохранённую повторно. Сетевая неопределённость после принятия запроса провайдером не позволяет гарантировать exactly-once тарификацию; число повторов ограничено. Истечение сессии или изменение состава/ревизии не позволяет старому результату стать актуальным.

429 и временные 5xx повторяются с ограниченным backoff; задержка хранится в nextAttemptAt, PHP не спит минутами. Ошибки ключа, доступа, оплаты и формата требуют исправления причины. Ответ провайдера и ключ не вставляются в текст ошибки. Публичная ошибка содержит документ/часть через documentId/chunkStart, статус и безопасное объяснение. Успешный OCR и ручные правки не уничтожаются после ошибки другого этапа.

XLSX обрабатывается программно через ZIP/XMLReader с сохранением листа и ячейки. Рисунки не читаются, формулы не исполняются, формула без сохранённого результата даёт неизвестное значение. Макросы и опасные XML-конструкции отклоняются. Строки итогов остаются ячейками; превращение строк в товарные позиции выполняется отдельно при сопоставлении, с защитой от дублирования.

После OCR выполняется отдельное сопоставление OCR/ячеек с реестром, с закреплённым prompt customs-mapping-v1 и JSON Schema. Сопоставление разбивается по объёму контекста и разрешённым полям; успешные части также сохраняются. Поле вне реестра или неверный тип отклоняются. Ссылки на документы/страницы/ячейки и цитаты проверяются, исходные значения сохраняются рядом с программной нормализацией. Отсутствие текста ведёт к пустой редактируемой форме, а не выдуманному ответу.

Одинаковые нормализованные значения объединяются с несколькими источниками. Разные значения становятся кандидатами, поле не заполняется автоматически. Выбор кандидата и ручная правка имеют разные состояния. Новые предложения не перезаписывают их; новое противоречие требует проверки. Юридические коды, которые не следуют непосредственно из первички (например, представление документа или преференции), исключены из AI-заполнения и требуют ручного решения.

OCR сам по себе не означает проверенную декларацию. Уверенность OCR и соответствие JSON Schema не гарантируют смысловую правильность юридического поля. Весь путь OCR → сопоставление → сохранение ручной правки проверен на подменённых ответах; реальный ключ и успешный прогон Mistral ещё не подтверждены.
