# Матрица граф ИМ 40

Источник пользователя: `reference/rules/Книга1 (2).xlsx`, один лист «Лист1», диапазон A2:E60. Принятая версия источника: SHA-256 `a013d4f4f2ad62c5ee29ad23108eb58ef9e5b67b0c1b566698623ab46ef071aa`. В книге 57 позиций: 1–54, 15a, 17a и графа «В»; 14 пометок «не заполняется». Формул и изображений нет.

Пересборка: `php bin/build-graph-matrix.php`. На Windows с переносимым PHP: `.local-tools/php/php.exe bin/build-graph-matrix.php`. Результат `resources/registry/graphs.sources.v2.json` сохраняет порядок, названия, три приоритета и исходные адреса ячеек. Сборка использует существующий безопасный XlsxReader, не вычисляет формулы и не вызывает AI.

Это исходная матрица, не исполняемые юридические правила. Комментарий `398 (всегда)` сохраняется как часть источника; последнее решение пользователя требует `KZ` из единого официального классификатора в исполняемой графе 17а. Результаты 12/45–47 считаются программно, количества и льготы не выводятся из одной пометки «автоматическое заполнение». Применимые поправки и стадии задаются отдельным реестром граф.

Проверка `GraphMatrixTest.php` в PHP-наборе подтверждает hash, все номера, исходные названия и приоритеты, 14 неприменимых строк и воспроизводимость runtime-ресурса. При согласованном обновлении книги необходимо проверить изменения правил, обновить версию/hash и проверки; нельзя автоматически объявить новую матрицу юридически полной.

Книга нужна для локальной подготовки. На хостинг передаются готовые runtime-ресурсы; Downloads и первичка в release не требуются.

Исполняемая привязка хранится в `graph-bindings.v2.json`; `php bin/build-graph-registry.php` объединяет её с матрицей в `graphs.im40.v2.json` и закрепляет hash локальной инструкции `DT_2026.docx`. Для каждой позиции определены режим, область, условие применимости, стадия, пустое состояние и typed field bindings. Номер правила `DT:15(N)` отсылает к инструкции заполнения соответствующей графы. Это предварительный профиль обязательности D4/D7, не юридическое заключение по всем возможным случаям.

14 пометок книги видимы как неприменимые и не проверяются. 12/45–47 — будущие результаты. Все остальные применимые исходные графы проверяются до перехода; 39 зависит от явного ответа о квоте, 41 — от единиц ТН ВЭД. Параметры метода 1, расходы/распределения, ставки и фактическая уплата («В» внутри 47) доступны на стадии расчёта. Участники 2/8/9/14 и транспорт 18/21/25/26 связываются с конкретной ролью/этапом. Общие поля не размножаются на товары; товарные 31–47 сохраняют отдельные сущности.

1 — ИМ/40; 5 и 32 следуют структуре подтверждаемых товаров; 17а — KZ. 36 не получает отсутствие льгот из молчания; 37 не получает неизвестную предыдущую процедуру; 41 получает единицу из ТН ВЭД, но не неизвестное количество; 54 получает дату, но не выдуманного составителя. Для этих неизвестных UI показывает «не удалось заполнить автоматически» с `value=null`. Числа 0 и ответы false не являются пропусками.

GET `/api/registry` содержит `graphs`, GET `/api/session` — `graphProjection`: версия/profile/dataRevision и 57 позиций, entries с fieldId/entityId/address/value/status/required/evidenceIds/placeholder. Это проекция typed draft, не второй независимый документ. При неактуальном расчёте 12/45–47 имеют pending_calculation и null. Неизвестные автоматические поля имеют auto_unavailable и точный placeholder; not_applicable отдельно. Значения нескольких товаров адресуются по id. Названия стран выводятся из того же alpha-кода, числового дубля нет.
