## Что не доказано этими тестами

### Доработка прикрепления

До изменения UI локальная проверка реального нажатия «Прикрепить файлы» в Edge прошла: filechooser открылся, PHP принял multipart с file, groupId и актуальной revision, вложение сохранилось. Отмена/повторное открытие и выбор того же файла проверены. Отказ именно на пользовательском хостинге не воспроизведён; его конкретная причина не установлена. Выявлен лишний шаг интерфейса: выбор вида сам не создавал строку до «+ Добавить». В новой редакции строка создаётся сразу; прикрепление остаётся синхронным пользовательскому нажатию, пустой выбор не вызывает upload.

`tests/upload.browser.mjs` проверяет настоящий filechooser и поля, реально принятые PHP, вместо чтения бинарного multipart через CDP (Edge его не предоставляет). Там же проверяются выбор мышью/Enter, отсутствие дублей, ошибка сохранения с повтором и отдельное создание записи графы 44. Эти проверки не требуют Mistral и не доказывают условия PS.kz.

Удаление проверяется AttachmentDeletionTest и HTTP/браузерным путём: непустая группа удаляется одной revision, оставшийся источник и его OCR сохраняются, выбранное значение становится ручным без удалённой цитаты, автозначение без источника очищается. Покрыты ссылки графы 44, исходные строки, mapping/checkpoints, чужие/устаревшие/активные операции и повтор файловой очистки с запретом выхода из каталога сессии. Ошибка одного из нескольких файлов не теряет допустимые вложения; новый UI показывает её в своей строке.

`tests/upload-recognition.browser.mjs` работает с реальным PHP API и явно синтетическими переходами worker через закрытый тестовый router. Проверены отдельный счётчик ошибок, ожидание mapping после полного OCR, автоматическая проверка при обычном результате/готовом кэше, ручная форма после трёх видов конечных ошибок, refresh, восстановление соединения и отклонение позднего polling. Этот router отсутствует в release. GraphPipelineTest дополнительно подтверждает, что повторный start активного пакета не перезапускает упавший файл, а исчерпанные OCR/mapping lease заканчиваются; реальный HTTP-транспорт теста parallel-ocr запускает 20 запросов до первого ответа.

Команды: `.local-tools/php/php.exe tests/php/run.php`; `node --test --test-concurrency=1 tests/*.test.mjs`; `node --test tests/graphs.browser.mjs tests/upload.browser.mjs tests/upload-recognition.browser.mjs`; `npm run build`; `.local-tools/php/php.exe bin/build-release.php`; `.local-tools/php/php.exe tests/release-smoke.php`. Прямой `npm test` в этой ограниченной Windows-среде получил spawn EPERM при запуске дочерних test-процессов; полный тот же набор прошёл прямой командой Node с последовательным запуском файлов.

В новом прогоне Mistral не вызывался: OCR/structured mapping проверяются воспроизводимыми ответами, включая ошибки и подтверждение цитат. Это проверяет обработку, но не измеряет полноту реального распознавания новых сканов. Старый отчёт Document AI не переносится как оценка качества нового prompt/профиля. НБК использует сохранённый реальный XML за 28.10.2026 и отдельно обозначенные синтетические ответы; внешние ошибки моделируются, TLS не отключается.

Пять товаров — проверочные данные, не утверждение о наличии пяти товаров в каждом реальном инвойсе. Примеры ДТ/ДТС — материал сравнения; их регистрационные номера/статусы и спорные веса/коды не присваиваются новой декларации. Неоднозначные многодокументные PDF и группы товаров требуют проверки пользователем.

Предварительная обязательность, база НДС, действующая применимость тарифа, условные новые позиции классификатора и границы метода 1 остаются явно описанными в [правилах профиля](graphs-mvp.md) и [справочниках](classifiers.md). Совместимость с Keden не заявляется. Реальные замеры памяти/времени/диска, HTTPS к провайдерам, cron и откат на PS.kz проверяются по [инструкции размещения](ps-kz-xs.md).
