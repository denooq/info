# Реестр полей MVP

Источник истины: `resources/registry/fields.v1.json`, версия 0.1.0, предварительный профиль ИМ 40 KZ / ДТС-1 метода 1. Это исполняемые метаданные формы и валидации, а не подтверждение юридической полноты.

Каждое поле имеет устойчивый `id`, `scope` и `key`, тип, единицу для десятичных величин, способы получения (`extract`, `calculated`, `reference`, `manual`), правило, `requiredWhen`, проверки `validWhen`, подсказки источников и назначения PDF/XML. Незаполненное значение — `null`; boolean не получает автоматического false. Фиксированные ИМ/40/ЭД/метод 1 принадлежат выбранному профилю, а не извлекаются из чужой зарегистрированной ДТ.

Условия `eq/all/any/not` — декларативные данные без eval; сравнение строгое. `eq` с null включает неизвестное/отсутствующее значение. Участники хранятся отдельно по ролям; `sameAsRole` означает явное совпадение, не молчаливое копирование адресов. Строки первичных таблиц и товары ДТ — разные сущности.

`matrixCoverage` и `dtsMatrixCoverage` связывают каждое семейство таблиц D6 с конкретными полями. Поля служебных граф и неприменимые для профиля графы отмечены в `nonApplicable`, не превращаются в обязательные инпуты.

Привязки XML разделены по профилям. `sample-observed` означает наблюдавшийся элемент примера; `sample-family` — семейство с разными корнями по ролям/этапам; оба статуса ещё не означают XSD-проверку. `pending-xsd` имеет null вместо придуманного пути. `rule-only/model-only` — управляющие признаки модели, которым не приписывается самостоятельный элемент XML. Краткие корни D/S/I/V/VI определены в реестре; пространства имён ДТ и ДТС разрешаются независимо.

Проверка структуры и покрытия: `node --test tests/registry.test.mjs`. Поведенческие правила валидации и межполевые проверки добавляются отдельно; эта команда не утверждает успешную генерацию PDF/XML.
