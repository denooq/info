# Трёхстраничный MVP · 23.11.2026

Это описание предыдущей версии формы. Актуальные редакторы и обязательность — в [compact-graphs.md](compact-graphs.md), нормативные правила — в [catalogs-and-calculations.md](catalogs-and-calculations.md), результаты текущей проверки — в [acceptance-compact.md](acceptance-compact.md). Отдельные поля участников/документов, ручные ставки и условия приёмки хостинга ниже не относятся к текущей форме.

Текущий профиль — `im40-kz-graphs`. Страницы: документы → проверка граф → расчёт. Предыдущие PDF/XML-генераторы сохранены как неактивный код: HTTP confirm/create/generate/download возвращает EXPORT_DISABLED, задания generate не принимаются. XSD, оболочка Keden и неподдержанная XML-ветка не являются условием проверки/расчёта. Служебные номера, регистрация, выпуск и подпись не присваиваются.

## Документы

Начальных выбранных видов нет. Пользователь ищет официальный код/фрагмент названия и выбирает результат мышью или Enter: строка «код — официальное наименование» сохраняется сразу, без отдельного «+ Добавить». Ввод запроса строку не создаёт, повторный выбор того же вида использует существующую. Ошибка сохранения видна, доступно «Повторить добавление». В графе 44 и при исправлении вида сохраняется отдельное явное действие.

Справа в строке «Прикрепить файлы» открывает системный диалог с множественным выбором. Имена и короткие статусы вложений видны ниже; отмена ничего не меняет, диалог можно открыть снова и выбрать тот же файл. Поиск продолжается кнопкой «Показать ещё»; доступны клавиатура, Escape, причины недоступности. Синонимов, транслитерации и AI-поиска видов нет. Можно изменить вид группы или назначить вид старому вложению без повторного OCR. Один допустимый файл позволяет начать распознавание; отсутствие другого вида не блокирует загрузку. Общие квоты применяются к сессии.

Полный справочник, происхождение и даты — [classifiers.md](classifiers.md), роль вида в приоритетах — [source-roles.md](source-roles.md). Пустая группа не создаёт документ или реквизиты 44. Файл и юридический документ — разные сущности: один PDF может содержать контракт и дополнения, документ может иметь несколько вложений.

Крестик у вложения удаляет только файл; крестик в заголовке строки удаляет вид вместе со всеми его файлами одной версией данных. Ошибки загрузки показываются с именем файла под своим видом, допустимые файлы из того же выбора сохраняются. Чужая/устаревшая версия и изменение вложений при активном OCR/mapping отклоняются сервером.

При удалении очищаются цитаты, связи кандидатов и файловые ссылки записей графы 44, исходные строки и зависимый mapping/расчёт. Кандидат с оставшимся источником сохраняется; автозначение без источника пересматривается. Ручное или выбранное пользователем значение и ручная запись документа остаются без ссылки на удалённый файл. Успешный OCR остальных файлов не удаляется. Физическая очистка ограничена проверенными путями своей сессии; при отказе файловой системы список повторов хранится приватно, очистку повторяет существующий cleanup, затем действует TTL. Новая cron-задача не нужна.

Если проверка уже была открыта и новых нераспознанных файлов нет, удаление последнего скана сохраняет доступ «К проверке данных» без новой загрузки. Ручные обязательные реквизиты по-прежнему проверяются перед расчётом.

После добавления файлов внизу доступна кнопка «Распознать документы». Прикрепление само не запускает AI. Во время текущего пакета заблокированы повторный запуск и изменение вложений; успешные OCR-части переиспользуются, неуспешные имеют ограниченные повторы. Разные файлы обрабатываются параллельно существующим worker, дополнительные cron на каждый файл не нужны.

Прелоадер показывает «Распознано документов: N из M», ошибки отдельно. Страницы/части файла и задания сопоставления не увеличивают N. После OCR остаётся стадия «Заполняем графы декларации…», затем автоматически открывается вторая страница. Немедленный готовый ответ из кэша также открывает её. Частичные/полные конечные ошибки и отказ mapping ведут к ручной проверке с диагностикой, обязательность перед расчётом сохраняется. Обновление страницы восстанавливает ожидание без нового OCR; ошибка сети сохраняет данные и предлагает проверку соединения. Старый ответ другого набора/сессии не подменяет результат.

## Графы

На второй странице 54 основных блока из книги с подписью меньшим жирным шрифтом «Графа N». 15а/17а вложены в 15/17, «В» — в 47. Карточки идут одной вертикальной колонкой на всех ширинах; высота каждой следует содержимому. Общие сведения сохраняются один раз. Переключатель товаров меняет 31–47, сохраняя id/массы/цены/коды/связи. Составные реквизиты остаются структурированными; технического раздела Keden нет.

Один уникальный допустимый кандидат заполняется автоматически без кнопки выбора. Разные значения показываются кнопками по рангу с источником на hover/focus. Основной источник не подавляет противоречие резервного. Одинаковые нормализованные значения объединяют цитаты. Ручные значения не стираются поздним mapping; новый противоречащий источник требует проверки. Неизвестный автоматический реквизит показывает «не удалось заполнить автоматически», в данных остаётся null. False и 0 — значения, не пропуски.

Графа 6 принимает подтверждённое число мест из транспортного документа/упаковки. Если известен только общий счёт и нет ручных групп, создаётся одна внутренняя группа «Места поставки»; это не маркировочный номер из первички. Для единственного товара связь однозначна. Для нескольких товаров связи подтверждаются пользователем; общее количество считает уникальные группы один раз. Ручная правка группы сохраняется. Создание/исправление доступно внутри 6/31.

В 44 сразу видны поля инвойса/контракта и непустых выбранных видов. Это формы-предложения: запись появляется по первой правке, номер/дата не берутся из имени файла. Наименование вида берётся из классификатора; связь с единственным товаром однозначна, при нескольких выбирается явно. Дополнительный документ можно добавить через официальный селектор без файла. Повторные правки используют существующий id. Файл не заменяет реквизиты документа.

## Обработка

OCR работает параллельно с прежними retry/тайм-аутами/checkpoints. После окончания всех попыток mapping берёт только полностью recognized-файлы; terminal failed не удерживает пакет. Если все файлы завершились ошибкой, открывается ручная форма с диагностикой. Повторяются лишь неуспешные OCR-части; успешный OCR сохраняется при remap/смене вида. Mapping fingerprint включает виды/версии, матрицу, prompt, состояние источников; поздний ответ старого плана отменяется.

AI получает разрешённые поля/графы, приоритеты, официальный вид/роль и известные товары. Ответ ограничен JSON schema и server-issued sourceId. Backend проверяет цитату, единицу, формат, роль и идентичность. Неподтверждённый вид не предоставляет значения чужой графе; замечание видно в форме. Данные документа не исполняются как инструкции. AI не рассчитывает платежи и не выбирает обязательность.

Ключи документов/расходов локальны для файла: одинаковое `invoice` не сливает разные инвойсы. Транспорт связывается по этапу. Разрешительный перечень не создаёт товары. Повторный файл с тем же hash/видом сопоставляется один раз. Разные сканы без надёжной общей идентичности не склеиваются по одному названию. Состав товаров подтверждается; повторные сведения и отдельные строки можно объединять с разной арифметикой или разделять внутри 31. Качество сканов и многодокументных PDF требует проверки человеком; совпадение цифр само по себе не доказывает юридическую идентичность.

## Две проверки

`reviewValidation` проверяет все применимые обязательные исходные графы. Пустая 8 блокирует переход даже при достаточной арифметике. Неприложенный файл не блокирует, если реальные необходимые реквизиты внесены вручную, включая 44. Четырнадцать «не заполняется» не проверяются. 12/45–47 до расчёта — pending_calculation; суммы заранее не требуются. Gate действует и на прямые `/api/review/complete` и `/api/calculate`.

`calculationValidation` добавляет метод 1, расходы/вычеты/распределения, продавца/покупателя ДТС, ставки/основания и нужные валюты. Все эти поля доступны на третьей странице. Ошибка ведёт к графе/полю, переключая нужный товар. Опрос, 401 или ошибка сети не создают новую сессию и не сбрасывают форму. Blur и следующий клик используют последовательную очередь и свежую revision.

Дата — день Казахстана при создании черновика; refresh не меняет её. KZT=1, курс 23 соответствует валюте 22/дате 54. USD и валюты расходов/специфических ставок нужны на расчёте. Точная дата, номинал, ошибки и ручное основание НБК описаны в [exchange-rates.md](exchange-rates.md).

## Расчёт и допущения

Существующий полный ТН ВЭД задаёт код, единицы и базовые ставки. Точное подтверждённое название может выбрать код; неоднозначное сохраняет варианты. Неизвестный документальный код не заменяется молча. Базовая ставка требует подтверждения применимости по дате/происхождению/льготам/исключениям/сноскам. Две единицы требуют двух количеств. Количество не выводится из названия единицы. НДС/сборы, неизвестные льготы/предыдущая процедура/составитель не копируются из примеров.

Brick Math сохраняет пять формул пошлины, номиналы, HALF_UP и точное распределение копеек. Включённый транспорт не добавляется повторно. Статистическая стоимость отдельна. База НДС `(стоимость + пошлина + сбор)` остаётся предварительным допущением по примерам; акциз не поддерживается. «В» использует фактическую уплату, не начисление 47. Ручная сумма не заменяет формулу: расхождение требует исправления операндов/пересчёта либо принятия вычисленного значения.

Проекция 12/45–47/«В» относится к одной dataRevision. Правка снимает расчёт, возврат к графам не запускает OCR. Файлы не публикуются. Проверка PS.kz XS, тайминги/память/очистка на аккаунте — отдельная невыполненная приёмка; локальные fixtures не заменяют её и не доказывают 100% распознавания.
