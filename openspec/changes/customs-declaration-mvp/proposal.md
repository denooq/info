# Proposal

## Why

Текущее приложение показывает большой технический реестр вместо понятных граф ДТ; тип вложения и приоритет источника не закреплены в процессе сопоставления, а ошибка одного OCR удерживает весь пакет. Перепланирование от 23.11.2026 переводит существующий MVP на три страницы и таблицу граф пользователя, сохраняя проверяемые источники, ручные правки и программный расчёт.

## What Changes

- **BREAKING:** заменить четыре страницы на «Документы → Графы ДТ → Расчёт». Убрать результат, «Создать», скачивания и запуск PDF/XML из активного приложения; XSD и расширения Keden больше не ограничивают этот сценарий.
- **BREAKING:** первая страница — пустой селектор с поиском по официальному наименованию или коду полного классификатора документов, затем «+ Добавить» и несколько файлов выбранного вида. Без сокращённого списка, синонимов и AI-поиска видов. Не требовать загрузки конкретных документов; сохранять технические лимиты файлов.
- Передавать код выбранного вида в OCR/mapping-контекст и применять матрицу источников и приоритетов из «Книга1 (2).xlsx». Сохранять источник каждого кандидата; один уникальный допустимый результат заполнять без кнопки, разные значения показывать кнопками в порядке приоритета. Подтверждённое противоречие не скрывать более высоким приоритетом.
- Сохранить параллельный Mistral Document AI для PDF/изображений, программное чтение XLSX, временные OCR-checkpoints и отдельное структурированное сопоставление. Окончательная ошибка файла не должна блокировать заполнение по остальным; успешный OCR не повторять при изменении правил или типа документа.
- **BREAKING:** вторая страница — 54 номерных блока с названиями из книги и меньшей жирной подписью «Графа N». Все 57 позиций книги сохраняются: 15а/17а внутри 15/17, «В» внутри 47. Общие данные вводятся один раз, товарные — отдельно для каждого товара. Применимые реквизиты и ручное редактирование остаются внутри граф.
- Автозначения получать из применимого правила, справочника либо расчёта. При неизвестном автоматическом значении показывать «не удалось заполнить автоматически» с null в данных. Пометки «не заполняется» исключать из обязательности данного профиля. Числовые значения, количество и уплату не выдумывать.
- **BREAKING:** не открывать расчёт до заполнения всех применимых обязательных исходных граф, даже если арифметических входов достаточно. Отсутствие файла не является самостоятельной ошибкой, когда обязательные сведения внесены вручную. Производные результаты не создают циклическую блокировку до расчёта; его дополнительные параметры доступны на третьей странице.
- Использовать уже загруженный полный ТН ВЭД для кода, базовых ставок, единиц и сносок; не создавать второй каталог кодов. Для стран использовать единый полный официальный классификатор с буквенными кодами, включая KZ; комментарий 398 в книге переопределён последним решением пользователя.
- Сохранить дату заполнения нового черновика как текущий день Казахстана и курсы НБК на эту дату с кратностью. Сохранить метод 1, несколько товаров, точную арифметику, распределения и обязательный пересчёт при изменениях.

За границами остаются БД, регистрация, кабинет, история, постоянный архив, другие процедуры/методы оценки, отправка в Keden и ЭП. Новые бизнес-модули, редакторы справочников, синонимы селектора и генерация файлов в этот план не входят.

## Capabilities

### New Capabilities

В openspec/specs/ нет опубликованных основных спецификаций. Поэтому это ADDED-delta к будущему основному набору; существующие пути delta данного изменения сохранены. Код приложения уже существует — это переработка, а не greenfield.

- `declaration-classifiers`: полный официальный каталог видов документов и стран, строгий поиск и единые коды.
- `document-session`: выбранные виды и несколько вложений, временные сессии, ограничения и PS.kz.
- `document-extraction`: OCR, типизированные источники, приоритеты, цитаты и частичные ошибки.
- `declaration-review`: графы книги, ручной ввод, кандидаты, несколько товаров и обязательность перехода.
- `customs-calculation`: отдельные проверки входа/расчёта, метод 1, платежи и пересчёт без выдачи файлов.
- `exchange-rates`: текущая дата Казахстана и точные датированные курсы НБК.
- `tnved-selection`: поиск в предоставленном каталоге, ставки/единицы и подтверждение применимости.
- `declaration-export`: явное отключение прежней выдачи PDF/XML и её блокировок в текущем профиле.

### Modified Capabilities

Нет опубликованных основных capability для MODIFIED-delta. Все перечисленные delta этого изменения пересмотрены согласованно; требования прежнего четырёхстраничного плана заменены, не действуют параллельно.

## Impact

Затрагиваются React-страницы и маршрутизация, PHP upload/session API, Pipeline, Mapper, CandidateMerger, реестр граф/обязательности, Validator, адаптер Calculator, справочники и сборка. Стек PHP 8.3 + React/TypeScript/Vite, PS.kz Plesk XS, закрытые временные файлы и PHP cron сохраняется. Новые источники — датированная версия полного официального классификатора и книга пользователя; отдельная инфраструктура не нужна.

Материалы: reference/rules/DT_2026.docx, обе первички, reference/TNVED/tnved.json, примеры reference/expected-output/ и интерфейс. Внешняя книга находится в Downloads; её SHA-256 и полная матрица зафиксированы в design.md. Примеры зарегистрированных ДТ не являются источником новой декларации. Неподтверждённые актуальность справочников, привязка отдельных документов, полнота правовых правил и фактические ограничения PS.kz явно перечислены в дизайне.

Прежний план имел 74/75 выполненных задач. Это описание исходного состояния, а не доказательство реализации новых требований. Новый tasks.md содержит только невыполненные задачи переработки и отдельную фактическую проверку размещения; текущая подготовка изменяет только плановые артефакты.
