# Proposal

## Why

Подготовка ДТ ИМ 40 и ДТС требует переноса одних и тех же сведений из разнородных первичных документов, разрешения противоречий и проверки расчётов. MVP сократит ручной перенос: распознает документы, предложит значения с источниками и сформирует согласованный комплект файлов после проверки пользователем.

## What Changes

- Добавить русскоязычный сценарий из четырёх страниц: **загрузка → проверка данных → расчёты → скачивание**. Визуальный стиль: белый фон, просторная компоновка, тонкие серые границы, прямоугольные синие кнопки и синяя рамка активного поля.
- Принимать несколько PDF, JPEG/PNG и XLSX одним списком без обязательного распределения по видам документов. Поддерживать несколько файлов одного вида и дополнительные документы.
- Распознавать PDF и изображения через Mistral Document AI; читать ячейки XLSX программно. Отдельным AI-вызовом сопоставлять извлечённые факты с заранее определённым реестром полей ДТ и ДТС. Сохранять документ, страницу либо ячейку каждого предложения. Отсутствующие сведения оставлять пустыми.
- Показывать поля по разделам и товарам. Строка поля: название, редактируемый ввод и кнопки значений-кандидатов; источник показывать при наведении/фокусе. Нажатие кандидата подставляет значение. Пропуски, противоречия и ручные изменения видимы пользователю.
- Проверять все применимые обязательные исходные поля декларации и ДТС перед переходом к расчётам. Использовать предварительный реестр обязательности на основе `reference/rules/DT_2026.docx`, примеров и правил MVP; спорные положения явно документировать и сообщать в обсуждении, не откладывая из-за них разработку.
- Поддержать несколько товаров, их документы и распределение общих расходов. Рассчитывать стоимость, платежи и итоги программно с точной десятичной арифметикой. Редактирование запускает пересчёт; противоречие итогов формулам блокирует создание файлов.
- Ограничить ДТС формой **ДТС-1, метод 1**. Случаи неприменимости метода останавливать с объяснением, без переключения на другие методы.
- Из единой подтверждённой версии данных создавать PDF ДТ с необходимыми дополнительными листами/продолжениями и ZIP ровно с двумя XML: ДТ и ДТС. После изменения данных прежние расчёты, подтверждение и файлы становятся неактуальными.
- Ориентировать XML на предоставленные примеры и проверять официальные части по соответствующим XSD ЕАЭС. Расширения Keden проверять отдельно; совместимость с Keden и успешный импорт не заявлять без проверки точного формата.
- Разворачивать подготовленный из Git проект на **PS.kz, виртуальный хостинг Plesk, XS**: PHP backend и заранее собранный React/TypeScript frontend; временные файлы/JSON и задания PHP по расписанию. API-ключ хранить только на backend.

За границами MVP: БД, регистрация, личный кабинет, история деклараций, постоянный архив, отправка в Keden, ЭП, другие таможенные процедуры, методы оценки 2–6, отдельный PDF ДТС, дополнительные бизнес-модули и автоматический подбор юридически значимых ставок/разрешений без подтверждённого основания.

## Capabilities

### New Capabilities

- `document-session`: загрузка файлов, изоляция и ограниченный срок жизни временной сессии, состояние обработки на выбранном хостинге.
- `document-extraction`: OCR, чтение XLSX, сопоставление фактов с полями, подтверждаемые источники и обработка ошибок Document AI.
- `declaration-review`: реестр полей, четыре страницы, выбор кандидатов, ручной ввод, несколько товаров и обязательность данных.
- `customs-calculation`: ДТС-1 метода 1, стоимость, платежи, распределения, пересчёт и проверка арифметической согласованности.
- `declaration-export`: подтверждённая версия, PDF ДТ, XML ДТ/ДТС, XSD-проверки и согласованное скачивание.

### Modified Capabilities

Нет: существующих спецификаций и кода приложения в проекте пока нет.

## Impact

Появятся frontend, PHP API, файловое временное хранилище, PHP-задания обработки/очистки, интеграция Mistral, версионируемые правила и справочники, генераторы PDF/XML/ZIP и проверяемая сборка для Git/Plesk. Redis, сервер Node.js/Python, постоянно работающий worker и внешняя БД не требуются.

Материалы проверки: `reference/source-documents/`, `reference/source-documents/example2/`, `reference/expected-output/`, `reference/rules/` и фотографии `reference/interface/`. Готовые зарегистрированные декларации служат материалом сравнения, но не источником для автоматического заполнения новой декларации. В репозитории отсутствуют XSD и полный комплект правил ДТС; точный формат Keden будет уточнён пользователем позже. Ограничения хостинга, происхождение ставок, XML-расширения и остальные допущения подробно перечислены в `design.md`.
