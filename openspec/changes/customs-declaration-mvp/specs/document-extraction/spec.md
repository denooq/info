# Spec Delta

## Purpose

Извлекать факты из выбранных документов и заполнять заданные графы ДТ по матрице источников с цитатами, явными приоритетами и сохранением ручных решений.

## ADDED Requirements

### Requirement: Separate recognition from graph mapping
Система SHALL применять Mistral Document AI к PDF/изображениям, читать XLSX программно и отдельно сопоставлять результаты с заданными графами. OCR, страницы, таблицы и ячейки SHALL сохраняться до истечения сессии. Смена правил сопоставления MUST NOT повторять успешный OCR неизменённого файла.

#### Scenario: Remap a known file under changed priorities
- **WHEN** для уже распознанного файла изменились приоритеты или подтверждённый вид
- **THEN** сопоставление использует сохранённый текст и новые правила без повторного OCR
- **AND** устаревшие автоматические решения пересматриваются, ручные не теряются

### Requirement: Recognize files concurrently and tolerate terminal file errors
OCR разных файлов SHALL выполняться параллельно в пределах лимита пакета с отдельным прогрессом и ограниченными повторами. После завершения попыток всех файлов система MUST сопоставлять успешно прочитанные источники, не ожидая успеха файла с окончательной ошибкой.

#### Scenario: One file fails permanently
- **WHEN** часть файлов распознана, а один окончательно завершился ошибкой
- **THEN** графы заполняются по успешным источникам, ошибка файла видна и форма доступна
- **AND** повторная обработка не дублирует успешные OCR-части и активные задания

### Requirement: Apply document types and the workbook source matrix
Кандидаты SHALL соотноситься с графой, товаром и подтверждённым видом источника. Основной, второй и третий источники MUST следовать матрице книги. При отсутствии подтверждённого реквизита основного источника SHALL использоваться следующий; неподходящий источник MUST NOT автоматически заполнять графу.

#### Scenario: Find gross mass through a fallback source
- **WHEN** транспортный документ не содержит брутто, а упаковочный лист содержит подтверждённую массу соответствующего товара
- **THEN** графа 35 получает кандидата второго приоритета с источником и единицей
- **AND** масса нетто, общий вес другой партии или перечень разрешённых товаров не принимаются как брутто этого товара

### Requirement: Preserve distinct alternatives regardless of source rank
Система MUST объединять эквивалентные значения с сохранением всех источников. Единственное допустимое уникальное значение SHALL заполняться автоматически. Разные подтверждённые значения SHALL оставаться альтернативами, упорядоченными по приоритету; более низкий приоритет MUST NOT скрывать конфликт.

#### Scenario: Conflicting values at different priorities
- **WHEN** два допустимых источника для графы дают разные веса одного товара
- **THEN** автоматический окончательный выбор не выполняется, показаны обе кнопки и их источники
- **AND** выбор пользователя разрешает конфликт, ручная правка сохраняется

### Requirement: Verify every extracted value and reject document instructions
Каждый применяемый AI-кандидат MUST иметь допустимое поле, тип, единицу, товар и точную цитату со страницей либо ячейкой. Содержимое документов SHALL рассматриваться только как данные. Неподтверждённые значения, служебные номера готовой ДТ и инструкции из документов MUST NOT применяться как факты новой декларации.

#### Scenario: OCR contains an instruction or an unverified number
- **WHEN** текст предлагает игнорировать правила либо AI ссылается на отсутствующую цитату
- **THEN** инструкция не исполняется, кандидат отклоняется с объяснимой причиной
- **AND** отсутствующие реквизиты не восстанавливаются из примера зарегистрированной декларации

### Requirement: Preserve shipment and documentary identity
Строки инвойса SHALL сопоставляться с товарами без создания новых товаров по одному разрешительному перечню. Файл, юридический документ и товар MUST сохранять отдельную идентичность. Несколько файлов одного документа или несколько документов внутри PDF MUST NOT автоматически удваивать товары, стоимость либо записи графы 44.

#### Scenario: A combined contract file contains an annex
- **WHEN** один PDF содержит контракт и приложение, а второй файл повторяет часть этих сведений
- **THEN** источники сохраняют реальные страницы и связи, дубликаты фактов не суммируются
- **AND** неуверенная связь документа или товара требует проверки вместо создания пустых сущностей

### Requirement: Report provider failures without leaking secrets
Ошибки доступа, бюджета, формата, сети и ограничений Mistral SHALL различаться. Повторы временных ошибок MUST быть ограничены; постоянные ошибки MUST NOT создавать бесконечный цикл. Ключи, заголовки авторизации и закрытые пути SHALL отсутствовать в публичной диагностике.

#### Scenario: Provider returns a rate limit
- **WHEN** запрос получает 429 во время обработки других файлов
- **THEN** остальные продолжаются, успешные результаты сохраняются, повтор ограничен задержкой и числом попыток
