# Spec Delta

## Purpose

Подбирать код ТН ВЭД товара из предоставленного справочника по его наименованию, сохраняя проверку пользователем и происхождение значения.

## ADDED Requirements

### Requirement: Use only terminal codes from the supplied catalogue
Автоматический справочный подбор MUST использовать только существующие десятизначные конечные записи `reference/TNVED/tnved.json`, сохранять ведущие нули, hash версии, полное наименование и первоисточник. Справочник MUST включаться в runtime-сборку вместе с базовыми ставками, единицами и связанными сносками версии 2.

#### Scenario: Import supplied file
- **WHEN** выполняется подготовка справочника
- **THEN** проверяются 18014 уникальных записей, 13294 конечных кода, имена, родители и ссылки на первоисточники
- **AND** ресурс приложения работает без доступа к `reference/` на хостинге

### Requirement: Match names conservatively
Система SHALL автоматически заполнять единственное точное совпадение по названию; неоднозначный поиск SHALL сохранять варианты и необходимость выбора, неизвестное название SHALL оставлять код пустым. Дополнительный русский поисковый перевод AI SHALL опираться на подтверждённое название товара, не добавляя состав/назначение и не генерируя сам код.

#### Scenario: Distinct chemical name
- **WHEN** подтверждено название «этилацетат» либо ETHYL ACETATE с русским поисковым переводом
- **THEN** код 2915310000 подставляется из каталога и помечается справочным подбором

#### Scenario: Ambiguous product
- **WHEN** известно только общее название «клей»
- **THEN** система предлагает несколько найденных конечных позиций с полными наименованиями и предлагает уточнить описание
- **AND** обрезка списка для UI не делает первый результат однозначным

### Requirement: Preserve edits and shared output data
Подбор MUST выполняться отдельно для каждого товара, обновляться при изменении описания, сохранять документальный/ручной код и происхождение решения. Код SHALL редактироваться через существующее поле; PDF/ДТ/ДТС SHALL брать значение из одного подтверждённого snapshot.

#### Scenario: Edit description after automatic selection
- **WHEN** меняется описание товара с автоматически подобранным кодом
- **THEN** старые справочные предложения пересматриваются в той же ревизии данных и предыдущий расчёт/комплект инвалидируется
- **AND** ручной код не перезаписывается автоматически

### Requirement: Apply base tariff data with explicit context confirmation
После выбора кода система SHALL подставлять базовую формулу ЕТТ с операндами, сносками и источниками. base_rule MUST NOT считаться effective_rule. Применимость к дате, стране, происхождению, льготам и национальным исключениям MUST подтверждаться пользователем; изменение контекста или операндов SHALL сбрасывать подтверждение. Ручные ставки SHALL сохраняться.

#### Scenario: Chemical tariff
- **WHEN** выбран 2915310000 без ручной ставки
- **THEN** подставляется базовая пошлина 5%, отсутствие дополнительной единицы и источник
- **AND** расчёт ждёт подтверждения применимости; НДС не заполняется справочником

### Requirement: Keep reporting units distinct and quantities sourced
Дополнительные единицы SHALL подставляться по коду; две единицы SHALL требовать два количества. Количества MUST NOT выдумываться. Единица ставки MUST NOT подменять дополнительную единицу товара. Связанное количество SHALL меняться через исходную массу или количество товара.

#### Scenario: Specific rate quantity
- **WHEN** ставка задана за кг нетто
- **THEN** количество пошлины связано с массой нетто и пересчитывается при её изменении
- **AND** единица отчётности не подменяется единицей ставки, а отсутствующее отдельное количество требуется ввести
