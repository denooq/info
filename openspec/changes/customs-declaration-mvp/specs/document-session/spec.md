# Spec Delta

## Purpose

Обеспечивать загрузку файлов по выбранным официальным видам документов в изолированной временной сессии без регистрации, БД и истории деклараций.

## ADDED Requirements

### Requirement: Add official document types before attaching files
Первая страница SHALL начинаться с селектора полного классификатора и действия «+ Добавить». После выбора вида SHALL появляться строка с официальным кодом, наименованием и прикреплением нескольких PDF, JPG/JPEG, PNG или XLSX. Заранее заполненного сокращённого списка MUST NOT быть.

#### Scenario: Attach several invoices
- **WHEN** пользователь находит вид 04021, добавляет его и прикрепляет два допустимых файла
- **THEN** оба файла видны под выбранным официальным видом с именами, состояниями и удалением
- **AND** обновление страницы сохраняет выбранный вид и вложения той же сессии

### Requirement: Do not require an uploaded document checklist
Отсутствие вложения определённого вида MUST NOT запрещать распознавание остальных файлов. Пустая добавленная строка MUST NOT считаться документом или источником значения. Распознавание SHALL быть доступно при наличии хотя бы одного допустимого вложения.

#### Scenario: Only a transport document is uploaded
- **WHEN** добавлен допустимый транспортный файл без инвойса, контракта и лицензии
- **THEN** обработка этого файла разрешена, остальные графы остаются доступными для ручного заполнения
- **AND** переход к расчёту всё равно требует обязательных исходных граф

### Requirement: Enforce technical upload limits
Система MUST проверять фактический формат, читаемость, размеры, число файлов, страниц и общий объём до платного OCR. Многократное добавление видов MUST NOT обходить лимит сессии. Ошибка SHALL указывать файл и причину, сохраняя остальные вложения.

#### Scenario: A file exceeds the configured limit
- **WHEN** файл повреждён, защищён паролем либо превышает технический лимит
- **THEN** он отклоняется с понятной причиной без скрытого усечения и потери допустимых файлов

### Requirement: Isolate and expire temporary sessions
Документы, OCR, кандидаты и расчёты MUST быть доступны только своей анонимной сессии и храниться вне публичного каталога. Успешные авторизованные действия SHALL согласованно продлевать cookie и срок бездействия; polling и worker MUST NOT продлевать его. После истечения доступ SHALL прекращаться, очистка удаляет данные.

#### Scenario: Concurrent users and expiration
- **WHEN** два браузера загружают разные документы и срок одной сессии истекает
- **THEN** данные между ними не доступны, истёкшие материалы удаляются без открытого браузера
- **AND** поздний ответ задания не восстанавливает удалённую сессию

### Requirement: Preserve saved work and bound processing
Система SHALL сохранять состояние между запросами, не создавать дубли заданий при polling или повторном запуске и восстанавливаться с checkpoints после прерывания. Ошибка соединения MUST NOT очищать форму или запускать новую сессию и OCR автоматически.

#### Scenario: Connection fails during manual editing
- **WHEN** сохранение получает сетевую ошибку либо SESSION_REQUIRED
- **THEN** видимая форма и несохранённый ввод остаются, пользователь может проверить прежнюю сессию
- **AND** новая сессия возникает только по явному действию после фактического истечения

### Requirement: Keep the agreed hosting and backend secrets
Приложение MUST сохранять возможность размещения на PS.kz Plesk XS готовым комплектом с PHP-задачами. БД, сервер Node/Python, постоянно работающий worker и новые cron на каждый документ MUST NOT требоваться. Ключ Mistral SHALL оставаться только на backend и отсутствовать в Git, браузере и журналах.

#### Scenario: Deploy the prepared application
- **WHEN** проверяются комплект размещения и фактические возможности web/cron PHP на PS.kz
- **THEN** ресурсы, зависимости, ограничения и ошибки конфигурации подтверждены измерениями
- **AND** успешная локальная сборка не выдаётся за выполненную проверку хостинга
