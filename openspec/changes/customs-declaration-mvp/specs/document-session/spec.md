# Spec Delta

## Purpose

Обеспечить загрузку первичных документов и работу с ними в изолированной временной сессии без регистрации, БД и постоянной истории деклараций.

## ADDED Requirements

### Requirement: Upload documents as one collection
Система SHALL принимать несколько PDF, JPEG/JPG, PNG и XLSX одним списком, включая повторяющиеся виды и дополнительные документы, без обязательного выбора категории.

#### Scenario: Add several files of the same kind
- **WHEN** пользователь выбирает или перетаскивает два инвойса, CMR и дополнительный документ
- **THEN** все файлы отображаются отдельными строками с именем, состоянием и возможностью удаления до обработки
- **AND** классифицировать файлы вручную для запуска распознавания не требуется

#### Scenario: Start recognition
- **WHEN** добавлен хотя бы один допустимый файл и пользователь нажимает «Распознать документы»
- **THEN** система запускает обработку текущего набора и показывает её состояние

### Requirement: Reject invalid or oversized uploads explicitly
Система MUST проверять фактический формат, читаемость и настраиваемые ограничения количества, размеров и страниц файлов до платной обработки; отклонение SHALL иметь понятную причину.

#### Scenario: Unsupported or damaged file
- **WHEN** загружен неподдерживаемый формат, повреждённый либо защищённый паролем документ
- **THEN** система указывает проблемный файл и причину, сохраняя остальные допустимые файлы
- **AND** переименование расширения не обходит проверку формата

#### Scenario: Hosting limit reached
- **WHEN** новый файл превышает действующий лимит загрузки или временного хранилища
- **THEN** система сообщает лимит и отклоняет добавление без скрытого усечения документа

### Requirement: Isolate temporary sessions
Система MUST предоставлять доступ к документам, распознанным данным, черновику и результатам только текущей анонимной сессии; данные SHALL храниться вне публичного каталога без постоянной БД и истории.

#### Scenario: Two independent users
- **WHEN** два браузера создают разные сессии и загружают документы
- **THEN** каждый видит только собственные файлы, поля, состояния обработки и результаты
- **AND** знание имени чужого файла или идентификатора задания не даёт к нему доступа

### Requirement: Expire and delete session data
Система MUST ограничивать срок сессии, по умолчанию двумя часами от создания, прекращать доступ по истечении срока и удалять все её документы, OCR, черновики, задания и результаты ближайшим циклом очистки.

#### Scenario: Session expires while the browser remains open
- **WHEN** срок сессии истёк, в том числе во время опроса состояния
- **THEN** последующие запросы не возвращают её данные и предлагают начать новую загрузку
- **AND** автоматический опрос не продлевает срок хранения

#### Scenario: Cleanup after processing or browser closure
- **WHEN** истёк срок сессии, даже если браузер закрыт или выполнялось задание
- **THEN** очистка удаляет её временные данные и поздний ответ обработки не восстанавливает их

### Requirement: Preserve progress across requests
Система SHALL сохранять состояние активной сессии между HTTP-запросами и обновлением страницы до истечения срока, без личного кабинета и списка прошлых деклараций.

#### Scenario: Refresh during recognition
- **WHEN** пользователь обновляет страницу во время распознавания
- **THEN** он видит текущее состояние той же сессии и не запускает повторную платную обработку автоматически

### Requirement: Bound asynchronous processing
Система SHALL обрабатывать документы и генерацию в ограниченных по ресурсам заданиях, показывать ожидание, ход и ошибки; повторное нажатие не должно создавать дубли одного задания.

#### Scenario: Repeated recognition request
- **WHEN** пользователь повторяет запрос запуска для неизменённого набора файлов, который уже обрабатывается
- **THEN** система возвращает состояние существующей обработки без второго параллельного запуска

#### Scenario: Worker interruption
- **WHEN** выполнение прервано ограничением хостинга
- **THEN** состояние не остаётся навечно «в обработке»: задача возобновляется с безопасной границы либо получает понятную ошибку
- **AND** успешно полученные данные и ручные правки сохраняются в пределах сессии

### Requirement: Protect backend configuration and uploaded content
Система MUST хранить ключ Mistral только в закрытой конфигурации backend, проверять принадлежность изменяющих запросов сессии и не публиковать секреты, тексты документов и временные пути в клиентском коде, Git или технических журналах.

#### Scenario: Inspect browser responses and release files
- **WHEN** проверяются frontend, ответы API, журналы и подготовленный к размещению комплект
- **THEN** в них отсутствует API-ключ, а документы и приватные настройки недоступны по прямому публичному URL

### Requirement: Support the agreed hosting target
Комплект размещения MUST работать на PS.kz Plesk XS средствами PHP, готовых статических файлов и PHP-задач по расписанию, без обязательной БД, SSH, серверов Python/Node.js и постоянно работающего worker.

#### Scenario: Deploy a prepared release
- **WHEN** пользователь размещает подготовленную Git-версию, задаёт приватную конфигурацию и настраивает PHP-задания в Plesk
- **THEN** полный сценарий и очистка выполняются после проверки необходимых PHP-возможностей и ресурсных ограничений аккаунта
- **AND** неподдерживаемая возможность хостинга сообщается как конкретная ошибка настройки
