# Spec Delta

## Purpose

Обеспечивать загрузку файлов по выбранным официальным видам документов в изолированной временной сессии без регистрации, БД и истории деклараций.

## ADDED Requirements

### Requirement: Add official document types before attaching files
Первая страница SHALL начинаться с селектора полного классификатора. Выбор результата мышью или Enter SHALL сразу создавать строку с официальными кодом и наименованием, без отдельного «+ Добавить». Повторный выбор того же вида SHALL использовать существующую строку. Поиск SHALL работать только по официальным коду и наименованию; заранее заданного сокращённого списка и синонимов MUST NOT быть.

#### Scenario: Attach several invoices
- **WHEN** пользователь выбирает результат 04021 и прикрепляет два допустимых файла
- **THEN** оба файла видны под выбранным официальным видом с именами, состояниями и удалением
- **AND** обновление страницы сохраняет выбранный вид и вложения той же сессии

#### Scenario: Search is not a document selection
- **WHEN** пользователь печатает запрос, затем выбирает официальный результат мышью или Enter
- **THEN** ввод запроса сам по себе не создаёт строку, а выбор создаёт её без второго подтверждения
- **AND** повторный выбор вида сохраняет имеющиеся вложения без дублирования строки

#### Scenario: Saving a selected type fails
- **WHEN** сервер отклоняет добавление строки либо соединение прерывается
- **THEN** интерфейс показывает ошибку и возможность повторить действие, не выдавая несохранённую строку за готовую к прикреплению
- **AND** остальные сохранённые строки и вложения остаются

### Requirement: Open a working attachment dialog from each row
Строка SHALL показывать справа действие «Прикрепить» с реально открывающимся системным выбором нескольких PDF, JPG/JPEG, PNG или XLSX. Имена файлов SHALL появляться только после прикрепления под выбранным видом. Отмена диалога MUST NOT менять вложения или запускать распознавание. Выбор вида на странице загрузки MUST NOT сам создавать юридическую запись графы 44.

#### Scenario: Attach from the row action
- **WHEN** пользователь нажимает «Прикрепить» и выбирает несколько допустимых файлов
- **THEN** открывается системный диалог, файлы загружаются в выбранную строку и получают видимые состояния
- **AND** после отмены либо завершения диалог можно открыть повторно; состояние других строк сохраняется

#### Scenario: One attachment fails validation
- **WHEN** в выбранном наборе один файл отклонён
- **THEN** ошибка с именем файла и причиной видна рядом с вложениями, допустимые файлы сохраняются
- **AND** загрузка сама по себе не запускает OCR

### Requirement: Delete a file or its whole document row
Пользователь SHALL удалять отдельное вложение либо строку вместе со всеми её файлами. Удаление MUST затрагивать только собственную сессию и актуальную версию данных. Во время активного распознавания или сопоставления изменение вложений MUST быть запрещено также на сервере. Оставшиеся строки, файлы и ручные данные SHALL сохраняться.

#### Scenario: Delete a populated row
- **WHEN** пользователь удаляет не обрабатываемую строку с двумя файлами
- **THEN** строка и оба вложения исчезают из сохранённой сессии, связанные временные материалы удаляются без доступа к чужим путям
- **AND** обновление страницы не возвращает их, остальные строки сохраняются

#### Scenario: Reject a stale or foreign deletion
- **WHEN** удаление относится к чужой сессии, устаревшей версии либо активному пакету обработки
- **THEN** сервер отклоняет действие с понятной причиной без частичного удаления вложений

### Requirement: Reconcile sources after attachment deletion
Удаление SHALL убирать ссылки на удалённые файлы из источников, кандидатов и связей записей документов. Значения с оставшимися источниками и ручной ввод SHALL сохраняться. Автозначение без оставшегося источника SHALL очищаться или требовать повторной проверки; подтверждённое пользователем значение SHALL сохраняться без ложной ссылки на удалённый файл. Зависимые сопоставление и расчёт SHALL становиться неактуальными.

#### Scenario: An alternative source remains
- **WHEN** удалён один из двух файлов, подтверждающих одно значение
- **THEN** значение и доступный оставшийся источник сохраняются, удалённый источник больше не предлагается
- **AND** успешное распознавание остальных файлов не повторяется только из-за удаления

#### Scenario: A user confirmed a value from a deleted source
- **WHEN** удаляется последний файл-источник вручную подтверждённого значения или ручной записи документа
- **THEN** подтверждённое значение и ручная запись сохраняются как пользовательские данные без ссылки на удалённый файл
- **AND** интерфейс не требует новой загрузки вместо допустимого ручного заполнения

### Requirement: Do not require an uploaded document checklist
Отсутствие вложения определённого вида MUST NOT запрещать распознавание остальных файлов. Пустая добавленная строка MUST NOT считаться документом или источником значения. Распознавание SHALL быть доступно при наличии хотя бы одного допустимого вложения.

#### Scenario: Only a transport document is uploaded
- **WHEN** добавлен допустимый транспортный файл без инвойса, контракта и лицензии
- **THEN** обработка этого файла разрешена, остальные графы остаются доступными для ручного заполнения
- **AND** переход к расчёту всё равно требует обязательных исходных граф

### Requirement: Enforce technical upload limits
Система MUST проверять фактический формат, читаемость, размеры, число файлов, страниц и общий объём до платного OCR. Многократное добавление видов MUST NOT обходить лимит сессии. Ошибка SHALL указывать файл и причину, сохраняя остальные вложения.

#### Scenario: A file exceeds the configured limit
- **WHEN** файл повреждён, защищён паролем либо превышает технический лимит
- **THEN** он отклоняется с понятной причиной без скрытого усечения и потери допустимых файлов

### Requirement: Isolate and expire temporary sessions
Документы, OCR, кандидаты и расчёты MUST быть доступны только своей анонимной сессии и храниться вне публичного каталога. Успешные авторизованные действия SHALL согласованно продлевать cookie и срок бездействия; polling и worker MUST NOT продлевать его. После истечения доступ SHALL прекращаться, очистка удаляет данные.

#### Scenario: Concurrent users and expiration
- **WHEN** два браузера загружают разные документы и срок одной сессии истекает
- **THEN** данные между ними не доступны, истёкшие материалы удаляются без открытого браузера
- **AND** поздний ответ задания не восстанавливает удалённую сессию

### Requirement: Preserve saved work and bound processing
Система SHALL сохранять состояние между запросами, не создавать дубли заданий при polling или повторном запуске и восстанавливаться с checkpoints после прерывания. Ошибка соединения MUST NOT очищать форму или запускать новую сессию и OCR автоматически.

#### Scenario: Connection fails during manual editing
- **WHEN** сохранение получает сетевую ошибку либо SESSION_REQUIRED
- **THEN** видимая форма и несохранённый ввод остаются, пользователь может проверить прежнюю сессию
- **AND** новая сессия возникает только по явному действию после фактического истечения

### Requirement: Keep the agreed hosting and backend secrets
Приложение MUST сохранять готовый комплект для PHP/Plesk без БД, сервера Node/Python и постоянно работающего worker. Ключ Mistral SHALL оставаться только на backend и отсутствовать в Git, браузере и журналах. Размещение, настройка и фактическая проверка PS.kz MUST NOT требоваться для завершения изменения.

#### Scenario: Verify the prepared package locally
- **WHEN** готовый комплект проходит локальную проверку
- **THEN** необходимые runtime-ресурсы и зависимости включены, ключи и приватные данные исключены
- **AND** доступ к PS.kz и действия на хостинге не являются условием завершения изменения
