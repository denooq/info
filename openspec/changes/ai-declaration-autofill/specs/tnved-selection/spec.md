# Spec Delta

## Purpose

Подбирать код товара через смысловое AI-сопоставление подтверждённых характеристик с предоставленным полным справочником ТН ВЭД и давать пользователю доступный поиск и проверяемые альтернативы.

## ADDED Requirements

### Requirement: Let AI perform semantic commodity matching
AI SHALL интерпретировать название, язык, транслитерацию и подтверждённые свойства товара для поиска в существующем каталоге. Система MUST NOT требовать программирования переводов каждого товара. Выбранный автоматически код SHALL быть конечной записью предоставленного справочника с подтверждённым основанием выбора.

#### Scenario: Classify the named chemical
- **WHEN** документы содержат ETHYL ACETATE без подтверждённого десятизначного кода
- **THEN** AI сопоставляет смысл названия с записью «этилацетат» и предлагает 2915310000 из каталога
- **AND** документ подтверждает название, а справочник отдельно подтверждает выбранный код

#### Scenario: A broad product name lacks essential properties
- **WHEN** указаны только «клей», GLUE или торговая марка без достаточных характеристик
- **THEN** неподтверждённые состав/назначение не добавляются и несколько подходящих позиций остаются вариантами
- **AND** единственный первый результат поиска не становится автоматически доказанным соответствием

### Requirement: Ground every code and parameter in the supplied catalogue
Подбор SHALL использовать тот же полный каталог, его версию, ведущие нули, единицы и базовые ставки. AI MUST NOT придумывать коды или дополнять короткий HS нулями. Существование кода SHALL проверяться сервером отдельно от смыслового решения AI и применимости тарифа.

#### Scenario: A document contains an eight digit HS code
- **WHEN** источник содержит 29153100
- **THEN** AI использует его как дополнительное свидетельство и выбирает полную запись только по каталогу и описанию
- **AND** десятизначный код не выдаётся за буквальную цитату первички

#### Scenario: A documentary code is not listed
- **WHEN** подтверждённый документальный код отсутствует в принятой версии справочника
- **THEN** показываются исходный код и необходимость проверки, без молчаливой подмены похожей позицией

### Requirement: Expose a functioning code and name search
Графа 33 SHALL иметь поиск по коду и названию в полном runtime-каталоге с доступным выбором результата. Пустой код MUST NOT открывать пустую панель ставок. Для одного подтверждённого AI-соответствия SHALL применяться автозаполнение, для разных допустимых вариантов — явный выбор.

#### Scenario: Search the catalogue manually
- **WHEN** пользователь вводит код или фрагмент наименования в поиск графы 33
- **THEN** возвращаются существующие записи с кодом и названием, выбор заполняет нужный товар
- **AND** отсутствие результатов показано явно, ввод каждой буквы не запускает платный AI-запрос

#### Scenario: Inspect rates before and after selecting a code
- **WHEN** код ещё не выбран, а затем выбран из каталога
- **THEN** сначала отсутствует пустая ссылка «Ставка и единицы», затем доступны сведения выбранной записи

### Requirement: Preserve item decisions and tariff dependencies
Коды и варианты SHALL принадлежать конкретному товару. Ручное решение MUST сохраняться при повторном AI-сопоставлении. Смена кода SHALL пересматривать единицы, фактические количества, ставки и актуальность расчёта; нормативная применимость MUST NOT подтверждаться одним выбором AI.

#### Scenario: Two items have different classifications
- **WHEN** пользователь меняет код второго товара
- **THEN** первый товар не меняется, несовместимые единицы/количества второго требуют уточнения и прежний расчёт снимается
- **AND** две требуемые дополнительные единицы по-прежнему требуют два соответствующих количества

#### Scenario: AI proposes a code after a manual selection
- **WHEN** сопоставление находит новое предложение для товара с ручным кодом
- **THEN** ручной код остаётся, новое противоречие доступно для проверки со своими основаниями
